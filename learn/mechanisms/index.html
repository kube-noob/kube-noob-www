Watch a request travel your own manifests

6 lessons on how a cluster works. Each is a walk: one path through a cluster, followed one hop at a time, with every hop graded against the manifests you give it. Watch one on an example first, then run it on your own.

Watch a walk in 62 seconds

What a walk says about each hop

holds
The objects the hop needs are there, and the rules that read them found nothing wrong.
BROKEN
A rule found something on this hop. The walk names the rule that broke it.
cannot judge
Something the hop needs is missing or unreadable. The walk stops there and does not call what follows fine.
not checked
No manifest can show this hop, so nothing judged it. On a card it is the outlined cube.

A hop nothing read is never reported as working. A walk ends complete (exit 0), broken (exit 1) or stopped with no verdict (exit 5), and each example below shows which.

Network

3 lessons

  • A request finds your Pod

    Follow one request from the edge to a container, hop by hop

    7 hops · 6 judged from your manifests · 1 not observable in a manifest

    • Watch example 1 complete · exit 0
    • Watch example 2 broken · exit 1
    Walk your own manifests
    kube-noob learn mechanism mech-net-request-to-pod -f ./manifests --format html > walk.html
    The 7 hops, in order
    1. There is an Ingress at the edge with nothing known-dangerous on it
    2. The Ingress routes to a Service that is here, on a port it serves
    3. The Service finds pods to send it to
    4. The workload owns the pods it selects
    5. The namespace has a network policy, and it is neither open nor inert
    6. The containers declare a readiness probe
    7. The packet crosses the node to the container not checked by any manifest

    The 7 hops, in order

  • A packet meets a NetworkPolicy

    Follow what decides whether a packet to one of your pods is admitted or dropped

    6 hops · 4 judged from your manifests · 2 not observable in a manifest

    • Watch example 1 complete · exit 0
    • Watch example 2 broken · exit 1
    Walk your own manifests
    kube-noob learn mechanism mech-net-network-policy -f ./manifests --format html > walk.html
    The 6 hops, in order
    1. The namespace has a NetworkPolicy
    2. Every NetworkPolicy here selects a pod that is here
    3. The cluster's network plugin turns the policy into rules on each node not checked by any manifest
    4. No NetworkPolicy here carries an ingress rule that is open to every source
    5. The node admits the packet a rule allows and drops the rest not checked by any manifest
    6. No network policy here stops the pods it selects from reaching cluster DNS

  • Deploy an app

    Follow a Deployment from the manifest you send to a pod that is ready for traffic

    9 hops · 5 judged from your manifests · 4 not observable in a manifest

    • Watch example 1 complete · exit 0
    • Watch example 2 broken · exit 1
    Walk your own manifests
    kube-noob learn mechanism mech-cp-deploy-an-app -f ./manifests --format html > walk.html
    The 9 hops, in order
    1. Nothing here is refused for its identity, its API version, its selector or a request above its limit
    2. The API server authenticates, authorizes, admits and stores the Deployment not checked by any manifest
    3. The Deployment controller creates a ReplicaSet, and it creates the Pods not checked by any manifest
    4. Every container declares the CPU and memory it asks the scheduler for
    5. The scheduler picks a node for each Pod not checked by any manifest
    6. Every ConfigMap, Secret, claim and ServiceAccount a pod names is in this namespace
    7. Every container names its image by digest
    8. The kubelet starts the Pod on its node not checked by any manifest
    9. The containers declare a readiness probe

Security

1 lesson

  • RBAC and ServiceAccounts

    Follow what stands between a pod's identity and the API, from the token it holds to the grants behind it

    7 hops · 6 judged from your manifests · 1 not observable in a manifest

    • Watch example 1 complete · exit 0
    • Watch example 2 broken · exit 1
    Walk your own manifests
    kube-noob learn mechanism mech-sec-rbac-and-serviceaccounts -f ./manifests --format html > walk.html
    The 7 hops, in order
    1. A ServiceAccount is here, and no pod spec leaves the automatic token mount on
    2. No RoleBinding or ClusterRoleBinding here names everyone as a subject
    3. No RoleBinding or ClusterRoleBinding here names the cluster-admin role
    4. No Role or ClusterRole here uses a wildcard in verbs, resources or apiGroups
    5. No Role or ClusterRole here carries a grant KN-S017 lists as a privilege-escalation path
    6. A Secret is here, and none of them is a long-lived ServiceAccount token
    7. The API server authorizes the request not checked by any manifest
