Website: what is out of date

The site lives in its own repository, which a working session has to be sourced at — it cannot be edited from a session attached to this one. So this file is the queue: anything shipped here that the site states differently goes in the table below when it is merged, and comes out when the site is updated. Numbers go stale faster than prose, so every number below names the command that prints the true value rather than repeating it in a second place.

Last site update: unknown to this file — record the date and the commit here when the next one happens. That gap is itself a defect of the same kind this file is about: a queue that cannot say when it was last drained cannot tell you whether 10 rows is a backlog or a morning's work.

The numbers the site quotes

Run this and compare it against every page that states a count. A page that states one of these and disagrees is wrong, not merely old: the compliance document said "The 78 audit rules" with 89 in the code for long enough to reach a reader (G206), and these are the same kind of claim.

python -c "import sys; sys.path.insert(0,'src'); from kube_noob import __version__; from kube_noob.audit.engine import list_rules; from kube_noob.audit.controls import RULE_CONTROLS; from kube_noob.audit.redteam import SCENARIOS; from kube_noob.debug.playbooks import PLAYBOOKS; from kube_noob.learn.tutor import curriculum; from kube_noob.toolkit import Toolkit; from kube_noob.config import load_settings; t=curriculum()['tracks']; print('version', __version__); print('rules', len(list_rules())); print('controls', len({c for cs in RULE_CONTROLS.values() for c in cs})); print('playbooks', len(PLAYBOOKS)); print('red-team scenarios', len(SCENARIOS)); print('tracks', len(t), 'lessons', sum(len(x.get('lessons',[])) for x in t)); print('MCP tools', len(Toolkit(load_settings()).specs()))"

As of 2026-11-08 at v0.9.2: version 0.9.2, 93 rules, 30 NIST SP 800-53 Rev. 5 controls, 67 offline playbooks, 9 red-team scenarios, 5 tracks with 16 lessons, 48 MCP tools. These seven figures are asserted against the code by tests/test_guidance.py::test_the_website_queue_states_the_real_numbers, so this paragraph cannot drift the way the compliance document's heading did. docs/scorecard.md and krew/noob.yaml are generated from the same source and are worth copying from rather than retyping.

Checklist for the weekend session

  1. Source the session at the site repository (this one cannot reach it).
  2. Run the facts command above in a checkout of THIS repository and work from its output.
  3. Walk the queue table top to bottom; delete each row as the site catches up, and record the date and commit at the top of this file.
  4. Check the install page against docs/install.md and the Formula/ directory rather than memory: Homebrew, pip, the container image, the Helm chart and the Claude plugin each have their own current instructions there.
  5. Positioning: the site must not call kube-noob an AI, an assistant, a chatbot or an agent. tests/test_brand.py and tests/test_guidance.py hold that line for this repository's copy; the site has no such test, so it is a manual read. "No AI inside. Works with yours." is the line.
